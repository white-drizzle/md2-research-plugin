# 论证规则（三大病症 → 规则）

提炼 MD → slide_plan.json 时，逐条对照：

## 病症 1：只有数据没有结论
- 每个发现必须是"结论 + 证据 + 启示"三段，禁止只写数据
- 反例：`对称面温度比中心低 1.2×`（只有数据）
- 正例：`炉腔对称 ≠ 温度对称 → 板位选择必须靠 CFD / 对称面低 1.2×（实验+仿真一致）/ 启示：不能看炉子对称就放心`
- `claim` 是页级结论，`so_what` 是工艺/决策启示。`claim_figure` 布局需两者齐备；`point_figure` 布局的结论由 `point.lead` 承载

## 病症 2：名词堆砌不解释
- 专业名词首次出现必须加 note 元素或行内解释
- 需解释的典型词：Zemax、ADRC、ITAE、Re、ESO、灰体假设、Tg、R2R、VIM、IPL、MET、TAL、热迁移
- 解释标准：一句人话，说明"它是什么 + 为什么这里提到它"
- 示例：`note: term="对称炉腔" explain="腔体左右镜像对称，但风扇扰流破坏对称"`

## 病症 3：图片与文字弱关联
- 每张图必须设 `figure.bound_to`，指到页内具体结论
- 若图不能证明页内任何结论 → 从本页移除，放别页或不用
- `interpretation` 必须说明"这张图证明什么"而非"这张图是什么"

### 图证双向绑定：选图与正文的衔接必须写进正文
`figure.bound_to` 把关联存在 JSON 里，但**听众看不到**。要让"图证绑定"成立，选图与正文的衔接必须在**幻灯片正文**里显式说出来：
- 结论元素（`point.lead` / `qa.question` / `ced.claim`）加 `fig_ref` 声明它由本页哪张图支撑
- 渲染时结论句自动加酒红前缀"**如图 xx 所示，**"（与图注 source 同色）——听众一眼把正文和图连起来
- 选图的同时写衔接：先想"这句结论靠哪张图、图里显示什么"，再定 `fig_ref`。**选择决策被写成正文，且机器可查**

### 三项机器校验（verify_plan 强制）
1. **每页图必须被至少一个正文元素 `fig_ref` 引用**——孤儿图（选了图但正文不提它）违规
2. **`fig_ref` 主图号必须与 `figure.source` 一致**——防图号漂移（图号权威源只剩 `source`，正文引用必须对齐）
3. **正文引用 `fig_ref` 但本页无 figure 违规**——引用了不存在的图

正例：`{ "type": "ced", "claim": "MET 焊点结合强度最优", "fig_ref": "6" }` → 渲染"**如图 6 所示，**MET 焊点结合强度最优"

## 数据纪律（不编造）
- 所有数值来自 MD 原文，不得推断、补全、美化
- 提取优先级：论文结论句 > 图表数据 > 正文数值
- 拿不准就标 `[原文存疑]`，宁可缺不可错
